## 1. Issue Description

User required elevated manager privileges following a promotion to Department Head. Due to missing administrative permissions, she was unable to approve purchase requests or access budget reports.

![Screenshot 1 Ticket](tickets/INC389824/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- Access to administrative tools, budget reports, and purchasing approval workflows is governed by **Role-Based Access Control (RBAC)** via the **Management** Active Directory security group.
- Nina Patel's account only possessed standard memberships (**Domain Users, Engineering, CodeRepo-Access**), so she lacked the group membership required for her new role.
- Reviewed ticket details confirming HR approval and VP authorization for the managerial access request.

---

## 3. Resolution Steps

1. Opened **Tools → Directory management** console.
2. Searched for user **Nina Patel (npatel)**.
3. Navigated to **GROUPS** under account management.
4. Selected **Management** from the dropdown and clicked **ADD** to provision the security group membership.

![Screenshot 2 Added to group](tickets/INC389824/screenshot-2-added-to-group.png)

5. Contacted Nina Patel via **Team Chat** to test her newly elevated privileges.
6. User confirmed full functionality: *"Yep, I just checked and it's all working now! Thanks so much for the quick fix!"*

![Screenshot 3 Solution](tickets/INC389824/screenshot-3-solution.png)

---

## 4. Root Cause & KB Notes

**Root Cause:** Administrative tool, budget report, and purchasing approval access is governed by RBAC through the **Management** security group. The user's account retained only standard memberships, so the promotion was not reflected in her Active Directory group assignments.

**KB Article:** KB-1072

**Quick Resolution Checklist:**
1. Open the Directory management tool from the Service Desk portal.
2. Search for the target user by name or username (samAccountName).
3. Select the user profile and navigate to the **GROUPS** tab.
4. Locate the required role-based security group (e.g., Management) from the group dropdown list.
5. Click **ADD** to bind the security principal to the target group.
6. Instruct the user to re-authenticate or refresh their active session tokens, then verify resource access.
