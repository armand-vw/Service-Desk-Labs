## 1. Issue Description

Network printer **Cafeteria-Printer-E** displayed as offline on the user's workstation, preventing print jobs from spooling. The physical printer was powered on with sufficient paper — the issue was at the client endpoint level. Daily cafeteria menus and event materials were affected.

![Problem](tickets/INC755877/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- Physical hardware was operational — the issue was a client-side TCP/IP mapping mismatch.
- The local endpoint held a **legacy IP binding** (`10.0.2.201`). Following network re-addressing, the printer's static IP had changed to `10.0.2.54`.
- Cross-referenced **Tools → Documentation Station → Print Server** to retrieve the authoritative updated IP.

![Documentation Check](tickets/INC755877/screenshot-2-documentation-check.png)

---

## 3. Resolution Steps

1. Connected to workstation **SD1027** (Michael Brown) via **Tools → Remote Support**.
2. Navigated to **Settings → Devices → Printers & Scanners** and identified the stale offline entry pointing to `10.0.2.201`.

   ![Printer Status](tickets/INC755877/screenshot-3-printer-status.jpg)

3. Removed the misconfigured printer profile.
4. Clicked **Add a printer or scanner** and entered the correct TCP/IP address `10.0.2.54`.
5. Installed using the Universal Print Driver — device status transitioned to **Ready** at `10.0.2.54`.
6. User confirmed successful print queue execution via Team Chat.

---

## 4. Root Cause & KB Notes

**Root Cause:** Client endpoint retained a stale TCP/IP port mapping (`10.0.2.201`) after network re-addressing changed the printer's static IP to `10.0.2.54`. Print requests never reached the physical device.

**KB Article:** KB-1063

**Quick Resolution Checklist:**
1. Verify current IP assignment under **Tools → Documentation Station → Print Server**.
2. Remote into the host endpoint (**Tools → Remote Support**).
3. Open **Settings → Devices → Printers & Scanners**.
4. Remove the offline printer with the old IP binding.
5. Click **Add a printer or scanner** → input updated IPv4 address and complete driver assignment.
6. Perform a test print and verify resolution with the end-user.
