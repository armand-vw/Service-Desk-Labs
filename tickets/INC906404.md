## 1. Issue Description

Organization-wide email outage: desktop mail clients were failing to connect, and the webmail portal was completely inaccessible.

![Screenshot 1 Ticket](tickets/INC906404/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- Navigated to **Tools → Server Room** and audited core server infrastructure (**DC01, DC02, FILESERV01, PRINT01, EXCH01**).
- Isolated the failure to **EXCH01** (Mail Server, Server Room A), which had entered a **DEGRADED** health state.
- Resource monitoring showed severe load spike exhaustion at **95% CPU** and **90% Memory** usage, preventing the Exchange Information Store and IIS web services from processing incoming/outgoing client requests.

---

## 3. Resolution Steps

1. Selected the options menu for **EXCH01** and triggered a **REBOOT** command.

![Screenshot 2 Server Reboot](tickets/INC906404/screenshot-2-server-reboot.png)

2. Monitored post-reboot telemetry until EXCH01 returned to an **ONLINE** status with normalized resource consumption (**18% CPU, 46% Memory**).
3. Contacted reporter Tom Wilson via **Team Chat** to verify service restoration.
4. User confirmed email access and connectivity were fully restored: *"Everything's working now, thanks a lot!"*

![Screenshot 3 Solution](tickets/INC906404/screenshot-3-solution.png)

---

## 4. Root Cause & KB Notes

**Root Cause:** EXCH01 entered a DEGRADED state due to severe resource exhaustion (95% CPU / 90% Memory), which halted the Exchange Information Store and IIS web services. A soft reboot cleared the thread backlog and restored service health to ONLINE.

**KB Article:** KB-1074

**Quick Resolution Checklist:**
1. Open the Server Room management interface under Tools.
2. Review the SERVERS tab to inspect core node statuses (DC, FILESERV, EXCH, PRINT).
3. Locate the primary Mail Server (EXCH01) and evaluate CPU/Memory load percentages.
4. If the node displays DEGRADED with high resource consumption, click the action menu (...) and select **REBOOT**.
5. Allow the server cycle to complete until its status transitions back to ONLINE and utilization metrics normalize.
6. Verify webmail page accessibility and confirm mail flow recovery with end-users.
