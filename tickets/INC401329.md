## 1. Issue Description

Desktop mail client stuck in a perpetual **"Trying to connect…"** loop with a **"Connection error"** notification. User was unable to send or receive messages on workstation SD1010. The same account synchronized without issue on the user's mobile device, and general web access on SD1010 was fully operational.

![Problem](tickets/INC401329/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- Account credentials and server-side services were validated — mobile mail synchronization functioned correctly.
- General network connectivity on SD1010 was confirmed operational.
- Fault was isolated to **local desktop application corruption** — damaged configuration files or cached execution binaries, not account locks or network routing issues.

![Problem Confirmation](tickets/INC401329/screenshot-2-problem-confirmation.jpg)

---

## 3. Resolution Steps

1. Connected to workstation **SD1010** (Tom Wilson) via **Tools → Remote Support**.
2. Confirmed the client application UI was hanging on connection initialization.
3. Opened **Control Panel → Programs and Features**.
4. Located **Mail Client (v16.0, 890 MB)** and selected **REPAIR** to restore corrupted local binaries and dependencies.

   ![Repair](tickets/INC401329/screenshot-3-repaired.png)

5. Confirmed the software entry updated to **REPAIRED**. Launched the client and verified active server handshakes.
6. User confirmed via Team Chat that email send/receive was fully restored.

---

## 4. Root Cause & KB Notes

**Root Cause:** Local desktop mail client application corruption — damaged configuration files or cached binaries. Server-side services and account credentials were intact (verified via mobile sync).

**KB Article:** KB-1064

**Quick Resolution Checklist:**
1. Confirm network connectivity and verify credentials function on an alternative endpoint (mobile device, webmail).
2. Connect remotely via **Tools → Remote Support**.
3. Open **Control Panel → Programs and Features**.
4. Locate **Mail Client** and click **REPAIR** (do not uninstall unless repair fails).
5. Allow the repair wizard to replace corrupted application state files and DLLs.
6. Launch the client, test send/receive, and verify resolution with the end-user.
