## 1. Issue Description

All 12 network printers across multiple floors displayed as **offline** and failed to process print jobs. Legal contract signing and executive presentations were blocked enterprise-wide.

![Problem](tickets/INC0012870/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- All 12 printers depend on a centralized print server (**PRINT01**) in Server Room B.
- A system-level freeze or crashed Print Spooler service on PRINT01 isolated print queues from all client workstations across the enterprise subnet.

---

## 3. Resolution Steps

1. Navigated to **Tools → Server Room → Servers** tab in the management portal.
2. Identified server **PRINT01** in a **Down** state.
3. Triggered an administrative reboot command to restart the system and reinitialize the Print Spooler service and network daemons.

   ![Server Reboot](tickets/INC0012870/screenshot-2-solving-problem.png)

4. Monitored until PRINT01 returned to **ONLINE** status (31% CPU, 47% Memory).
5. Confirmed successful print execution with the reporting user via Team Chat.

---

## 4. Root Cause & KB Notes

**Root Cause:** Single point of failure — a hung/crashed print server (PRINT01) knocked all 12 network printers offline. Print Spooler service freeze prevented queue routing from client workstations.

**KB Article:** KB-1058

**Quick Resolution Checklist:**
1. Verify the outage impacts multiple printers across different floors/subnets (rules out individual device/driver issues).
2. Navigate to **Tools → Server Room → Servers** tab.
3. Locate print server **PRINT01** and inspect host health status.
4. Execute a remote server reboot to clear hung spooler processes.
5. Monitor until status returns to ONLINE, then test print functionality with an end-user.
