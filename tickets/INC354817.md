## 1. Issue Description

Engineering employee Nina Patel reported that print jobs to the Floor 2 network printer **Floor2-Printer-B** failed with a **"printer offline"** error status. Coworkers were able to print without issue, indicating the fault was isolated to her workstation rather than the shared printer itself.

![Screenshot 1 Ticket](tickets/INC354817/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- Confirmed the physical printer was operational since other users printed normally.
- Cross-referenced the **Network Printers Reference Table** under **Documentation Station → Server Documentation → Print Server**, verifying **Floor2-Printer-B** is assigned static IP **10.0.2.51**.
- Opened a **Remote Desktop** session to workstation **SD1020** and inspected **Settings → Devices → Printers & Scanners**.
- The local printer profile still pointed to a legacy IP address (**10.0.2.199**) and showed status **Offline**.
- **Business impact:** blocked the generation of critical engineering reports.

![Screenshot 2 checking documentation](tickets/INC354817/screenshot-2-checking-documentation.png)

---

## 3. Resolution Steps

1. Connected to workstation **SD1020** (Nina Patel) via **Remote Desktop**.
2. Navigated to **Settings → Devices → Printers & Scanners** and identified the stale **Floor2-Printer-B** entry showing **Offline (10.0.2.199)**.

![Screenshot 3 Problem](tickets/INC354817/screenshot-3-problem.jpg)

3. Removed the stale **Floor2-Printer-B** profile using the **REMOVE** button.
4. Clicked **ADD A PRINTER OR SCANNER** and re-added **Floor2-Printer-B** pointing to the correct static IP **10.0.2.51**.
5. Verified the printer status displayed **Ready** at IP **10.0.2.51** and issued a test page.
6. Confirmed the fix with Nina via **Team Chat**: *"Yep, it's all working now! Thanks so much for the quick fix!"*

## 4. Root Cause & KB Notes

**Root Cause:** Following scheduled network maintenance, the user's local printer profile retained a legacy IP address (`10.0.2.199`) while **Floor2-Printer-B** had been re-assigned static IP `10.0.2.51`. Print requests never reached the physical device. The stale profile was removed and the printer re-added using the correct static IP.

**KB Article:** KB-1078

**Quick Resolution Checklist:**
1. Open **Documentation Station → Server Documentation → Print Server** and verify the current static IP address listed in the Network Printers Reference Table.
2. Connect to the user's computer via **Remote Desktop** and navigate to **Settings → Devices → Printers & Scanners**.
3. Inspect the active printer entry; if the IP address shown in parentheses does not match server documentation, click **REMOVE**.
4. Click **ADD A PRINTER OR SCANNER** and specify the correct IP address obtained from server documentation.
5. Verify that status displays **Ready** and run **PRINT TEST PAGE**.
6. Confirm print delivery with the user via **Team Chat** before closing the ticket.
