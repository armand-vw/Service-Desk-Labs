## 1. Issue Description

End-user was completely locked out of enterprise systems. Time-based one-time passwords (TOTP) generated by their mobile authenticator app were consistently rejected as invalid, despite appearing correct. User was unable to authenticate into any company systems.

## 2. Investigation & Triage

- Primary password credentials were verified as valid — the failure was isolated to the MFA layer only.
- Root cause: **time-sync drift** or token desynchronization between the user's mobile authenticator application and the authentication server's verification daemon.
- A full password reset was unnecessary; only the active MFA enrollment required clearing and re-initialization.

---

## 3. Resolution Steps

1. Navigated to **Tools → Directory** and searched for the user account (`ipetrova`).
2. Initiated contact via **Team Chat** with the user's designated manager to obtain authorization for MFA state modification.
3. Selected the target user profile, navigated to **Manage → Authentication**, and executed **Reset MFA** to invalidate the desynchronized token secret.

<img width="1918" height="870" alt="Screenshot 2 Solving problem MFA Reset" src="https://github.com/user-attachments/assets/a242a201-0083-4d92-abe9-e61d5ef559a1" />


4. Advised management and the user that the MFA state was cleared, enabling fresh authenticator enrollment on next login.
5. User successfully completed re-enrollment and regained access to all required systems.

---

## 4. Root Cause & KB Notes

**Root Cause:** TOTP token desynchronization between the user's mobile authenticator app and the authentication server. Primary password remained valid — no full account reset required.

**KB Article:** KB-1059

**Quick Resolution Checklist:**
1. Confirm user is entering current TOTP codes and that primary password is correct.
2. Verify identity or obtain manager approval via out-of-band communication.
3. Navigate to **Tools → Directory** → locate user profile.
4. Go to **Manage → Authentication** and click **Reset MFA** (do not perform full password reset unless password failure is confirmed).
5. Direct user to attempt a fresh login and follow prompts to re-enroll their authenticator device.
