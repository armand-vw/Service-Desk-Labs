## 1. Issue Description

Remote user reported that their primary web browser failed to load pages properly, returning **ERR_CONNECTION_TIMED_OUT** when navigating to internal intranet resources (`corp-intranet.servicedesk-simulator.com`) and rendering stale or broken versions of other sites. Secondary browsers and general network connectivity operated normally, isolating the fault to the primary browser's local profile.

![Screenshot 1 Ticket](tickets/INC648448/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- Underlying network connectivity, DNS resolution, and alternative browsers all functioned normally — pointing to **local browser state corruption** rather than a network or server fault.
- The `ERR_CONNECTION_TIMED_OUT` page explicitly advised clearing the browser cache and retrying.
- Root cause isolated to **corrupted cache/cookie files and invalid active session state tokens** within the primary browser profile.

![Screenshot 2 Problem](tickets/INC648448/screenshot-2-problem.jpg)

---

## 3. Resolution Steps

1. Established a remote support session to endpoint **SD1019** (Ivana Petrova) via **Tools → Remote Support**.
2. Verified the browser error state (`ERR_CONNECTION_TIMED_OUT`) when accessing web resources.
3. Opened the primary browser and navigated to **Settings → Privacy and security** (`browser://settings`).
4. Selected **Clear Browsing History / Clear Browsing Data**.
5. Checked **Cookies and other site data** and **Cached images and files**, then executed a full purge.
6. Confirmed successful completion via the UI indicator ("**Cache and cookies cleared**").
7. Relaunched the browser and verified internal web pages loaded without error.
8. Reached out to Ivana Petrova via **Team Chat**, who tested the sites and confirmed resolution: *"Yep, just checked, and it's all working now! Thanks so much for the quick fix!"*

![Screenshot 3 Solution](tickets/INC648448/screenshot-3-solution.jpg)

## 4. Root Cause & KB Notes

**Root Cause:** Local browser cache/cookie files had become corrupted and contained invalid active session state tokens. Network connectivity, DNS, and alternative browsers were unaffected, confirming the issue was strictly local storage corruption within the primary browser profile.

**KB Article:** KB-1069

**Quick Resolution Checklist:**
1. Confirm internet connectivity is active and secondary browsers load the target sites to isolate the issue to local profile corruption.
2. Connect to the affected user workstation (SDxxxx) via **Tools → Remote Support**.
3. Open the primary browser and navigate to **Settings → Privacy and security** (`browser://settings`).
4. Select **Clear Browsing Data / Clear Browsing History**.
5. Check **Cookies and other site data** and **Cached images and files**, then **Clear data**.
6. Restart the browser, navigate to the affected web application, and verify successful page loading with the user.
