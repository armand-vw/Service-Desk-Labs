## 1. Issue Description

User's second external monitor displayed **"No Signal"** and was not detected by Windows. The user confirmed the monitor and cables were functional by testing on a co-worker's laptop. Month-end close was in progress, impacting financial reporting.

## 2. Investigation & Triage

- Physical hardware and layer-1 connectivity were fully operational (verified by user cross-testing).
- Root cause isolated to a **corrupted or outdated display driver** on the local host, preventing the OS from initializing the external video output pipeline.

---

## 3. Resolution Steps

1. Established an elevated remote desktop session to workstation **SD1043**.
2. Launched **System Update**, scanned for available updates — identified **Integrated Graphics Driver v31.0.101.5186** (from v31.0.101.4887) among six pending updates.

<img width="1918" height="873" alt="Screenshot 2 Cheking for updates" src="https://github.com/user-attachments/assets/9baf58c0-3910-4884-8353-9f065d2d98e4" />


3. Installed the graphics driver update alongside companion system updates.
4. Rebooted the workstation to apply the new driver stack.
5. Dual-monitor display extension restored — user confirmed full resolution via chat.

---

## 4. Root Cause & KB Notes

**Root Cause:** Corrupted/outdated display driver prevented the OS from initializing the external monitor output pipeline.

**KB Article:** KB-1055

**Quick Resolution Checklist:**
1. Verify physical hardware and cabling are functional (test on alternate host).
2. Establish remote session to the target workstation.
3. Run **System Update** → install all available graphics/display adapter drivers.
4. Reboot to apply the new driver stack and confirm monitor detection.
