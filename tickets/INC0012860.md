## 1. Issue Description

Access modification request for employee **Kavita Patel (kpatel)** transferring from **Engineering** to **IT Infrastructure**. User lacked access to new department tools and files while still retaining unnecessary legacy Engineering access — a security risk through over-privileged account access.

## 2. Investigation & Triage

- Group Policy and resource permissions are managed via AD security group memberships.
- Failing to adjust groups following an internal role change creates access friction and violates the **principle of least privilege**.

---

## 3. Resolution Steps

1. Launched **Directory Management** tool and located user profile for `kpatel`.
2. Removed the legacy **"Engineering"** security group from the account.

## 4. Root Cause & KB Notes

**Root Cause:** Department transfers require manual AD group membership updates. Unchanged groups leave legacy access intact while blocking new department resources — a security and productivity issue.

**KB Article:** KB-1057

**Quick Resolution Checklist:**
1. Verify approved HR/manager transfer documentation.
2. Navigate to Directory / AD Administrative Center and search for the target user.
3. Remove the legacy department security group (e.g., Engineering).
4. Assign the new department security group (e.g., IT Infrastructure).
5. Notify user/manager to verify access propagation.
