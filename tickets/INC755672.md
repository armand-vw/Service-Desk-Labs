- Assigned ticket **INC755672** to the analyst queue.

## 3. Resolution Steps

1. Opened **Server Room → Servers** and located **DC01** (Domain Controller, Server Room A).
2. Executed a remote **REBOOT** command on DC01 to recycle the Local Security Authority Subsystem Service (LSASS) and Active Directory Domain Services (AD DS).
3. Monitored node recovery until DC01 returned to **ONLINE** status with healthy resource utilization metrics (18% CPU, 68% RAM).
4. Contacted David via **Team Chat** to verify domain logon functionality; reporter confirmed successful workstation sign-in and network access recovery: *"Give me one sec... yeah the internet is back! Awesome, thanks!"*

## 4. Root Cause & KB Notes

**Root Cause:** Primary Domain Controller (DC01) resource exhaustion and service degradation, spiking to 95% CPU and 95% Memory. A soft reboot recycled LSASS and Active Directory Domain Services, clearing service locks and restoring domain authentication across the organization.

**KB Article:** KB-1090

**Quick Resolution Checklist:**
1. Open **Server Room → Servers** in the administrative console to evaluate domain controller nodes (DC01, DC02).
2. Inspect DC01 node status, CPU, and Memory utilization for resource exhaustion or hung authentication services.
3. If DC01 is marked **DEGRADED**, perform a controlled reboot via **Action → REBOOT** to restart Active Directory Domain Services.
4. Verify the secondary Domain Controller (DC02) handles authentication requests during the failover window.
5. Monitor DC01 until node status returns to **ONLINE** and utilization normalizes below baseline thresholds.
6. Verify end-user domain logon ability and close the incident.
