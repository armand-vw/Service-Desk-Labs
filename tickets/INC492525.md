## 1. Issue Description

Desktop Mail client repeatedly prompted the user for authentication credentials despite entering the correct password. The client authenticated briefly before failing and displaying: *"Something went wrong and we couldn't sign you in. If the problem persists, try repairing Mail Client from 'Programs and Features' in the Control Panel."*

## 2. Investigation & Triage

- User confirmed using the correct password and Caps Lock was inactive.
- The system error message explicitly directed repairing the client installation — pointing to **local application state corruption**, broken registry keys, or damaged token cache files rather than an upstream credential mismatch.

## 3. Resolution Steps

1. Connected to workstation **SD1027** (Michael Brown) via **Tools → Remote Support**.
2. Attempted authentication within the Mail Client UI and observed the local sign-in error recommending an application repair.
3. Opened **Control Panel → Programs and Features**.
4. Selected **Mail Client (v16.0, 890 MB)** and clicked **REPAIR** to re-register software binaries and clear local authentication state caches.
5. Confirmed the application entry updated to **REPAIRED**. Re-launched the Mail client — successful password caching and authentication handshake.
6. User confirmed via Team Chat: "Oh, it's all working now! Thanks so much for fixing it!"

---

## 4. Root Cause & KB Notes

**Root Cause:** Local application state corruption — broken registry keys or damaged local token cache files caused repeated authentication failures. Server-side credentials and network connectivity were intact.

**KB Article:** KB-1066

**Quick Resolution Checklist:**
1. Remote into the target endpoint via **Tools → Remote Support**.
2. Verify credentials are correct (test via webmail or secondary endpoint).
3. If Mail client throws sign-in errors with valid credentials, open **Control Panel → Programs and Features**.
4. Locate **Mail Client** and select **REPAIR** to restore system files, registry keys, and local authentication caches.
5. Re-launch the Mail client and re-authenticate if prompted.
6. Verify sustained connectivity and confirm resolution with the end-user.
