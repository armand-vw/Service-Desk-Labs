## 1. Issue Description

Remote Marketing employee could not access campaign files on the corporate shared drive. File Explorer returned **"The network path was not found"**. A Q1 campaign deadline was imminent. External internet services (email, web) worked normally, but internal SMB shares failed.

## 2. Investigation & Triage

- VPN client was in a **DISCONNECTED** state, preventing internal network routing to corporate subnets.
- Previous drive mapping attempts used an invalid descriptive text string instead of proper UNC syntax.

<img width="1918" height="882" alt="Screenshot 3 VPN" src="https://github.com/user-attachments/assets/c6962b1d-de09-47e1-aef7-274d6d14fa3e" />


---

## 3. Resolution Steps

1. Connected to corporate VPN gateway (`vpn.corp.local:443` via IKEv2/IPSec).
2. Ran elevated terminal commands to purge stale DNS entries and enable persistent drive connections:

   ```
   ipconfig /flushdns
   net use /persistent:yes
   ```

3. Mapped drive `D:` to `\\FILESERV01\departments\Marketing` via File Explorer.
4. Verified mount point stability and file visibility — access fully restored.

## 4. Root Cause & KB Notes

**Root Cause:** Disconnected VPN prevented internal network routing to the file server. A secondary pathing error (descriptive string used instead of UNC) compounded failed mapping attempts.

**KB Article:** KB-1054

**Quick Resolution Checklist:**
1. Connect to Corporate VPN (IKEv2/IPSec)
2. `ipconfig /flushdns`
3. `net use /persistent:yes`
4. Map drive to valid UNC path: `\\FILESERV01\departments\Marketing`
