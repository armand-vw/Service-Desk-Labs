## 1. Issue Description

Remote employee unable to access corporate shared drives while working from home. The mapped network location `D: ENGINEERING DEPARTMENT DRIVE` showed an **OFFLINE** status in File Explorer, preventing access to critical project files, with **"network path not found"** errors.

![Problem](tickets/INC838819/screenshot-1-ticket.png)

---

## 2. Investigation & Triage

- SMB/CIFS share mappings require an active connection to the corporate domain network.
- Standard internet traffic works over local Wi-Fi, but internal SMB shares (`\\FILESERV01\...`) require an **active encrypted VPN tunnel** when off-premises.
- Stale network drive mappings need re-binding to establish valid SMB session tokens over the VPN virtual interface.

![Offline Share](tickets/INC838819/screenshot-2-problem.png)

![VPN Connected](tickets/INC838819/screenshot-3-connected-vpn.jpg)

---

## 3. Resolution Steps

1. Connected to host **SD1025** (David Wu) via **Tools → Remote Support**.
2. Confirmed VPN Client was connected to Corporate VPN Gateway (`vpn.corp.local:443`, IKEv2/IPSec).
3. Referenced **Tools → Documentation Station → File Server** to verify the UNC path:

   ```
   \\FILESERV01\departments\Engineering
   ```

   ![Documentation](tickets/INC838819/screenshot-4-checking-unc-path-doc.png)

4. Opened File Explorer → **Map Network Drive**, assigned **Drive Letter D:** to the UNC path.

   ![Mapping](tickets/INC838819/screenshot-5-mapping-drive.jpg)

5. Completed the wizard — mount status transitioned from OFFLINE to active **NETWORK DRIVE**.
6. User confirmed via Team Chat: "Yep, it's all working again now. Thanks a ton for the quick fix!"

---

## 4. Root Cause & KB Notes

**Root Cause:** SMB shares require an active VPN tunnel for off-premises access. A stale/offline drive mapping needed re-binding to establish valid SMB session tokens over the VPN virtual interface.

**KB Article:** KB-1067

**Quick Resolution Checklist:**
1. Connect to the user endpoint via **Tools → Remote Support**.
2. Open the VPN Client and ensure tunnel state shows **CONNECTED** to the corporate gateway.
3. Verify the target share path in **Documentation Station → File Server**.
4. In File Explorer, right-click **This PC → Map Network Drive**.
5. Assign the corresponding drive letter and enter the explicit UNC share path.
6. Verify folder contents populate correctly and confirm resolution with the end-user.
